# Releasing Memora

Memora ships through two complementary channels, for two different audiences:

- **Homebrew + GitHub Releases** distribute the `memora` CLI binary to end users
  (`brew install`, a `curl | sh` installer, and downloadable archives).
- **crates.io** publishes the libraries so Rust developers can embed the engine
  (`cargo add memora-core`) and the `Memora` facade.

They are not either/or. The CLI goes to Homebrew; the library goes to crates.io.

## 1. Bump the version

Versions live in two places that must stay in step:

- `workspace.package.version` in the root `Cargo.toml` (all crates inherit this).
- The three internal entries in `[workspace.dependencies]` of the root `Cargo.toml`
  (`memora-core`, `memora-llm`, `memora-mcp`), whose `version` is what crates.io uses.

Also update the `vX.Y.Z` mentions in `README.md`, `docs/src/introduction.md`, and
`docs/site/index.html`, move `CHANGELOG.md`'s `Unreleased` to the new version, then
commit.

## 2. Tag, which triggers the binary release (cargo-dist)

```bash
git tag vX.Y.Z
git push origin vX.Y.Z
```

The `Release` workflow (generated by [dist](https://opensource.axo.dev/cargo-dist/))
builds binaries for macOS, Linux, and Windows, attaches a shell installer, and
creates the GitHub release. Homebrew is intentionally **not** part of this workflow
(see step 4), which keeps every release run green.

## 3. Publish the libraries to crates.io

Publish in dependency order, because each crate must resolve the previous one from
the registry:

```bash
cargo login <crates.io-token>
cargo publish -p memora-llm
cargo publish -p memora-core
cargo publish -p memora-mcp
cargo publish -p memora-cli   # enables `cargo install memora-cli`
cargo logout
```

`memora-llm` and `memora-core` are the SDK; the others reserve the namespace and
enable `cargo install memora-cli`.

## 4. Update the Homebrew tap (manual)

The tap **`radotsvetkov/homebrew-memora`** is maintained by hand, so the release
pipeline needs no cross-repo token. After the GitHub release exists:

```bash
# Grab the new per-target hashes
gh release download vX.Y.Z -R radotsvetkov/memora -p '*.tar.xz.sha256'

# In a clone of radotsvetkov/homebrew-memora, edit Formula/memora.rb:
#   - bump the four release URLs to vX.Y.Z
#   - replace the four sha256 values
#   - keep `class Memora`, no `version` line, `bin.install "memora", "memora-mcp"`
ruby -c Formula/memora.rb                          # validate syntax
git commit -am "memora X.Y.Z" && git push
brew update && brew audit --formula radotsvetkov/memora/memora   # optional check
```

Users then install or upgrade with:

```bash
brew install radotsvetkov/memora/memora    # or: brew upgrade
```

To switch to **automatic** Homebrew publishing instead, add `"homebrew"` to
`installers`, set `tap = "radotsvetkov/homebrew-memora"` and
`publish-jobs = ["homebrew"]` in `dist-workspace.toml`, create a fine-grained
`HOMEBREW_TAP_TOKEN` PAT (contents:write on the tap) as a repo secret, and run
`dist generate`.
